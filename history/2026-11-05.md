1. **auto-ontology (NVIDIA)** — https://github.com/NVIDIA/auto-ontology
   Topic: AI/LLM 연구 및 모델
   Summary: Open-source framework builds a graph-based semantic ontology layer over enterprise databases so LLM agents answer business questions with verifiable SQL rather than guesswork. Pairs Postgres+pgvector catalog with FastAPI/LangChain + MCP server; auto-drafts business terms/joins from schema profiling, human-certifiable; 10 engine connectors (Postgres, Snowflake, Databricks, etc.); defaults to NVIDIA NIM/Nemotron. 4.9k stars, Apache-2.0. Every answer returns generated SQL + reasoning for auditability; no in-repo benchmark numbers (points to external BIRD text-to-SQL benchmark).
   Why it matters: Enterprise "chat with your data" teams get a reusable, auditable semantic layer instead of hand-rolling brittle text-to-SQL prompts.
   Status: ✅ verified

2. **kimi-k3-in-c (FareedKhan-dev)** — https://github.com/FareedKhan-dev/kimi-k3-in-c
   Topic: AI/LLM 연구 및 모델
   Summary: Hobby project implements inference for the 2.78-trillion-parameter Kimi K3 model in portable, dependency-free C99 — single CPU core, no GPU/BLAS/ML framework. Fits in 8.24 GB RAM via mxfp4 quantization + AVX2/SIMD MoE and linear-attention kernels. 10.3k stars, 1.6k forks, Apache-2.0.
   Why it matters: Shows trillion-scale MoE models can in principle run on ordinary consumer hardware via aggressive quantization and sparse-expert loading.
   Status: ⚠️ unverified: README gives no tokens/sec throughput figures or comparison to llama.cpp — speed/quality tradeoff beyond the memory-footprint claim is unconfirmed.

3. **FreeToken (FlashML-org)** — https://github.com/FlashML-org/FreeToken
   Topic: AI/LLM 연구 및 모델
   Summary: Open-source serving engine aiming to run large MoE LLMs (headline claim "290B+" params) on a single consumer gaming PC instead of datacenter hardware. Targets RTX 30/40/50-series GPUs; supports DeepSeek-V4-Flash, Qwen3.6-35B-A3B, GLM-5.2 in MXFP4/NVFP4/FP8/BF16; Anthropic/OpenAI-compatible APIs; CPU-GPU co-execution, double-buffered prefill streaming, global LRU expert cache with dynamic VRAM reallocation. Apache-2.0.
   Why it matters: If the claimed performance holds up, individuals could run near-datacenter-scale MoE models locally on gaming GPUs instead of paying for cloud inference.
   Status: ⚠️ unverified: No quantified tokens/sec, latency, or memory benchmarks in the README, and no direct comparison to vLLM/TGI/Ollama (a linked arXiv paper, 2608.16157, may contain the missing numbers).
